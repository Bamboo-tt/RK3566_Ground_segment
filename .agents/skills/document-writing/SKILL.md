# 项目技术文档编写

先按仓库 [AGENTS.md](../../../AGENTS.md) 与最新请求确定范围。全文任务读全部目标及相邻交接，局部任务只沿所需链路展开。项目资料入口与容易混淆的对象见[项目参考](references/项目参考.md)。

## 从真实对象建立连续主线

读取当前源件，确定板型、分支、配置与产物；旧正文帮助找线索。重写前列出需要保留的机制、算例、失败条件和章节归属。准确且清楚的内容保留，重复机制设一个主要讲解位置，其他章节补足当前交接并链接。

将构建产物、启动初始化和运行事件分别组织。构建关注输入、工具和输出；初始化关注提供者、消费者与依赖等待；运行关注事件、执行上下文、状态和接口。并行支线在真实汇合点连接，不用章节顺序冒充执行顺序。

机制章节在 H1 后先给清晰文本拓扑，展示入口、主要节点、分支和出口，随后简列核心源码或资料位置。复杂链路可拆子图。图与正文范围一致，章节沿处理过程推进，标题概括动作与机制，不机械套用统一栏目。

## 让概念解决当前问题

先说明控制目标与必要前提，再讲当前实现：先说明数据布局再解释索引，先说明量纲再计算，先说明资源持有再讨论释放，先说明保存状态与执行者再讲变化。沿同一个属性、触点、亮度或档位追到最终接口，例子尽量连续。

关键交接交代执行者、资源或数据、接口、完成条件和后续用途。先讲完整正常过程，再在对应节点补充异常、同步、竞争、挂起恢复和清理。专业概念展开到足以读懂实现，不补基础语法课，不将必要推导挪进问答。

## 核对实现，直接解释行为

分别核对硬件连线、属性解析、编译分支、函数调用及包内成员。找不到完整 BSP 时优先查与交付版本匹配的公开实现，记录稳定版本或提交链接；只有对照版本时，在影响结论的位置说明适用关系。不能从配置项、符号或模块存在补出没读到的调用链。

正文直接讲对象与行为，不组织成核验记录。不要反复添加证据标签、免责声明、未执行提醒或“能证明什么/不能证明什么”栏目。全书范围集中交代一次，局部只保留影响解释的具体条件。缺陷分析写清对象、触发条件、代码或电路原因、实际后果以及当前处理方式；未知环节指出缺少的具体实现，不用含糊提醒代替分析。

## 代码与图表承载不同信息

代码前给文件、函数或节点及当前职责，简短标明源码摘录、等价整理或伪代码。核心片段添加中文注释，解释单位、字段、边界、判断、同步范围、状态更新与清理顺序。省略处显式标出，保留决定行为的条件、错误处理和返回语义，不能拼接不同版本形成假函数。

图展示关系，代码展示行为，表格用于结构映射和同维度比较，段落解释原因与影响；同一机制不在四种形式中完整重复。数值演算先给输入及单位，坐标标明所在坐标系，GPIO 逻辑有效值、物理电平、IRQ 类型分别解释。

## 可连续阅读的 Markdown

使用中文与中性技术表达，连续段落承担推导，并列项才用列表。一个篇级 H1，章节 H2/H3 随章编号、不跳级，最多 H4；导航与索引按用途组织。标题独占一行、末尾不加标点，与正文空行，不以加粗短语代替标题。

围栏标语言，字符图用 `text`，保留源码缩进。仓库文件采用相对链接；含空格、中文、括号的目标用合适的尖括号或 URL 编码。源码链接同时提供函数、节点或属性定位。包内引用采用“包文件链接 + 包内成员路径”，不链接临时解包目录或伪造本机文件。

机制章末保留少量“核心工程问题与深度理解”，围绕串联机制、取舍或条件变化提问。每个问题紧接自己的回答，先回答再解释因果；不凑题，不背路径，不重复正文。资料索引和讲解提纲不强加问答。

## 一次完整检查后交付

沿读者顺序通读，检查前提、同一对象的交接、正常链路与异常位置；核对跨章板型、驱动、单位、极性和部署路径。对照保留清单防止删掉必要深度。

核查相对链接、锚点、包内成员、UTF-8、标题、围栏、表格和文本图，并实际渲染正文查看跳转与长行。对照最终差异和原件快照，确认只改授权文件。针对具体问题修正，交付简要说明保存的文件及实际完成的验证。
