# RK3566 学习文档呈现

公共标准以[项目 AGENTS.md](../../../../AGENTS.md)为准。先判断本轮是只读解释或审阅、局部排版还是已授权的内容重写，读取相关内容；重写时还应读目标全文和相邻章节，格式工作不能自行扩展成全书覆盖。

## 根据内容关系选择表达

正文优先使用连续自然段，把“问题为什么出现、机制怎样处理、结果交给谁”连起来。一段同时承担多种解释任务时按因果边界拆段，保留连接句；并列项目用列表，真正有先后依赖的动作才用编号步骤。长推导放在表格之外，表格用来比较共同维度或建立对应关系。

一个篇级 H1。编号正文第 07 章采用 `7.1`、`7.1.1`，其他章节类推；README 与维护文件不强套章节号。层级不跳跃，最多 H4，不以固定小节数或段落长度决定内容去留。标题概括对象与关系，不把所有标题写成口语问句。

## 代码、图示与引用

代码前说明环境、输入和目的，代码后解释关键步骤、返回值和下一步判断。片段与完整程序、示例值与实测值分别说明。围栏用准确语言；字符图和输出用 `text`，Markdown 中的结构图可用 `mermaid`。保留代码语义缩进，尤其 Makefile 的 Tab。

图示只承担一种流程视角；图中标出真正的执行者、产物或接口。正文解释图中容易误读的箭头，不能让图把缺失实现画成确定链路。能在简短文字或小表格中讲清的关系无需另加图。

正文中的工作区引用优先用相对路径，含空格或括号的目标使用尖括号或正确 URL 编码。源码引用同时给函数、节点或属性名，行号只是辅助。包内成员以“包文件链接 + 成员路径”定位，不能把它写成已存在的主机文件或板端路径。通用资料链接紧跟对应解释。

四类证据标记按段落或小节作用域使用，关键条件紧随结论。不要整段加粗或反复加警告；加粗只强调经过解释的重点。排版变化不得改变证据强度。

## 自查题与成稿检查

每章先独立列出少量自查题，再集中给相同编号的回答要点。题目可要求推理链、方案比较、算例或选择下一项检查；答案说明依据和结论边界。保留有价值的原题，不以统一题数为目标。

通读后检查编号、列表续号、表格、围栏、UTF-8、相对链接和实际预览。对格式整理还应比对差异，确认没有丢失关键公式、步骤、失败路径或限定条件。只读审阅报告具体位置、影响及建议；只读原理解释直接沿因果答复，不强套审稿模板或章节练习。没有实际预览时如实说明，不生成写入产物绕过范围。
