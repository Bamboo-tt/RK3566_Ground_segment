# RK3566 项目贯通

先读[项目 AGENTS.md](../../../../AGENTS.md)和[工作记录](../工作记录.md)，以本轮用户要求确认范围。只读审阅不写正文；明确要求重写时完成正文，不把技能建立当作正文交付。

## 确定主线与章节交接

本项目贯穿场景是：一套 CM3 与已选底板、屏幕及电池组合，从构建交付获得可启动系统；启动后各硬件资源被驱动取得；运行时图像、触点、电源状态和温控动作通过标准接口交给上层。场景用来连接知识，不表示当前实板已经验收。

整套改写时读[全流程蓝图](references/01_全流程蓝图.md)。每章围绕前文产物、当前约束、处理机制和后文输入建立连续叙述。驱动共性在第 05 章解释，外设章深入自己的正常路径与失败边界，验证章用这些因果关系决定检查次序；避免四处重讲同一份基础概念。

构建图描述源码、配置与文件产物；初始化图描述资源提供者、总线和 probe；运行图描述事件、数据和控制。并行链路在真实的交接处连接，不能把三类时间尺度画成一条执行链。

## 核对对象与事实

写具体机制前读[事实核查与维护](references/02_事实核查与维护.md)，再沿第 13 章资料索引读取当前源件。旧正文和记忆只帮助定位；不同板型、屏幕、驱动分支、基础 DTS 与包内 DTB、两种 overlay 包分别确定身份。

连续段落可集中标出所用证据类型，减少重复标签。静态风险同时写清对象、成立条件、可能影响及怎样取得运行证据；缺少 panel、CW2015 或启动工程源码时，通用机制只能解释必要前提，不能替项目补造实现。

## 让原理形成可追踪的过程

先沿正常路径说明谁在执行、从哪里取得资源、操作何种数据、通过哪个接口交给下一层。遇到新的约束才引入术语：例如先说明 I2C 等待会睡眠，再解释为什么需要工作线程或 IRQ 线程；先解释亮度是索引，再计算表长与默认值的关系。

关键路径再展开上下文、资源寿命、并发、失败与恢复。用具体状态转换说明按下/移动/释放、probe/回滚、挂起/恢复，不能把软件标志恢复等同硬件通信恢复。采用少量可复算的示例，注明示例与实测的区别。

比较方案时围绕同一个约束：静态 DTS 与产品 overlay、内建与模块、IRQ 与轮询、线程化 IRQ 与工作队列、逻辑亮度与物理电平，各说明解决的问题、代价和本项目适用范围。避免单独堆一章脱离调用路径的内核术语。

## 重写与维护

重写前建立简短的知识保留表：已有关键机制、证据、适用条件、拟落入的章节。重排后检查这些内容仍可找到，必要时将重复论述收敛到唯一章节并保留交叉链接。

正文完成后按[格式技能](../rk3566-chapter-format/SKILL.md)检查表达。通读应能从项目用途一直讲到一个外设的初始化、运行、故障和交付关系；再核对局部细节。文件数量、字数和链接数量只报告检查范围，不作为学习效果的证明。
