# 事实核查与维护

## 资料对象先于解释

以[第 13 章资料索引](../../../13_关键资料阅读索引.md)查当前文件，再记录本次结论针对的对象。必须分别辨认：6 英寸与 7 英寸屏幕；8 页地面站底板与 3 页相机网络底板；GT9XX 本地 V2.2 与供应商 V2.8.7；本地基础 DTS 与交付 DTB；同为 0.2.4 的普通/PWM overlay 包。

源码事实说明代码和配置表达了什么；包内事实说明某个确定文件带有什么；资料记录说明设计或历史操作；待确认事项指出缺少哪项对应证据。通用内核机制解释“如何可能工作”，不证明本 BSP 实际采用了该实现。

## 核查关键交接

| 交接 | 需要核对的两侧 | 常见错误 |
| --- | --- | --- |
| 原理图到设备树 | 连接器/网名/核心板脚位与 GPIO/pinctrl/供电引用 | 跨板型拼接、把逻辑有效误写成物理高低 |
| 设备树到驱动 | 属性名、GPIO API、regulator 名与实际解析函数 | 因 compatible 一致而忽略 binding 差异 |
| 触摸通知到采集 | IRQ 注册点、回调、work/timer 调用者 | 从函数名称推断执行上下文 |
| 命令表到面板动作 | 原始指令、转换记录头、驱动解析约定 | 把不同阶段相同数值的等待看作可互换 |
| 源文件到交付物 | 包哈希、配置、DTB 属性与编译符号 | 用相同名称或符号证明逐字同源 |
| 配置到运行 | 实际启动树、绑定驱动、接口与物理测量 | 用配置存在代替当前实板效果 |

缺少完整实现时应收窄项目结论，保留已证明的关系。可以引用版本明确的上游源码解释机制，但必须说明这是对照；不得把上游函数调用顺序、错误路径或补丁自动安到本 BSP 上。

## 最小而完整的交付检查

重写前读取完整章节及相邻交接，必要时建立临时知识保留清单。完成后沿蓝图通读，逐项检查已有技术内容和条件是否保留，合并重复解释时给出明确的跨章入口。

对新增事实检查原件；对引用检查实际路径和可检索定位；对图检查流程类型与箭头含义；对命令标出环境、检查目的、输出解读与未执行状态。主机算例可以复核，但结果不得变成板端实测。

最后查看 Git 差异及受保护原件内容，确认只改授权文档和规则。对 Markdown 做结构、链接和一次实际渲染检查；发现具体问题后针对性修正。工作记录写实际完成范围、检查结果、未执行事项，不复制整套规则或技术索引。
