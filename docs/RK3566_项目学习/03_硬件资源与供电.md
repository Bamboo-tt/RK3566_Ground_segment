# 03 硬件资源与供电：从一根控制线理解整块底板

上一章说明了内核、DTB、DTBO 和用户态怎样组成可启动的系统。现在要回答：这些软件产物究竟在控制什么？如果屏幕没有反应，应先确认哪个器件需要哪路电源、信号经过什么电路，再讨论驱动参数。

本章从面板供电这条实际线路出发，依次认识核心板与底板的分工、GPIO 电平与电源开关、引脚复用和电压域。到章末，读者应能把一项硬件功能整理成“连接对象、控制器、引脚、电源和有效条件”，交给下一章的设备树描述。

## 3.1 同一块屏幕需要几条独立通道

用户眼前只有一块触摸屏，Linux 面对的却是几个不同对象。面板要接收像素，触摸芯片要报告手指位置，背光要提供照明。三者的数据方向、供电和控制方法都不同，因此“屏幕不工作”还不是足够具体的问题。

CM3 核心板提供 RK3566 的计算能力、控制器及模块配套资源；自定义底板把这些资源接到屏幕、电池、风扇和连接器，并加入供电开关、信号隔离等电路。像素从核心板的显示控制器经 DSI 送到面板，触点经 I2C 回到核心板，背光则由 PWM 和供电使能控制。**一条通道成功，不能替其他通道证明工作正常。**

这里先明确材料对象。下文的电路推导主要依据 [8 页地面站底板原理图](../../原理图/SCH_RK3566底板V2_2025-10-21.pdf)：第 3 页是屏幕，第 4 页是电池，第 8 页是风扇。根目录的 [3 页底板原理图](../../SCH_RK3566底板V2_2025-11-21.pdf) 图内标识为 `3566cam_internet`，包含相机、网络和指示灯；它与地面站图有不同的管脚用途。两份图都属于设计资料，当前实板采用哪一份、是否改线，须用实物确认。

屏幕资料也要分组。7 英寸目录保存 800×1280、ILI9881C 和 GT9XX 相关材料，6 英寸目录保存另一套面板初始化、触摸代码和配置。尺寸相近或连接器相似，不能证明命令、供电要求及触摸配置可以互换。后面的显示与触摸章节会分别选择明确版本深入。

## 3.2 沿面板电源追到软件能申请的资源

### 3.2.1 GPIO 控制开关，电源来自供电网络

在旧底板第 3 页，先找到屏幕 FPC 上的 `VCC_LCD_MIPI`。沿供电路径往回走，经过 Q2 到达 `VCC3.3CW`；再沿 Q2 的栅极控制支路追踪，才会经过 Q4 到 `SDMMC0_D0_MIPI_EN_GPIO1_D5`。这是两条相互作用的路径：负载电流经 Q2 流向面板，GPIO1_D5 经 Q4 控制 Q2，GPIO 并不直接给整块屏幕供电。

Q4 是 NPN 三极管，Q2 是 P 沟道 MOS 管。GPIO 物理拉高时，Q4 导通并把 Q2 的栅极往低拉。MOS 管看的是栅极相对源极的电压 `VGS = VG − VS`：Q2 的源极接 3.3 V 输入，栅极降低后 VGS 变负，满足导通条件时就接通 `VCC_LCD_MIPI`。GPIO 拉低时，Q4 关断，上拉电阻让栅极回到源极电位附近，Q2 关闭。因此这份图纸表达的是物理高电平使能；实际贴装、压降和开关速度仍以测量为准。

Linux 需要表达“面板使用这路可开关电源”，而不希望每个 panel 驱动都知道底板用了 Q2 和 Q4。为此，它用 regulator 表示电源提供者。面板是消费者：请求开启供电，具体 GPIO 操作由对应电源驱动完成。这样换底板时通常修改资源描述即可，器件驱动仍围绕面板协议工作。

### 3.2.2 三项声明把接线转成依赖

本项目 [AIRCAS overlay](../../设备树包/aircas-compact-GCS_overlay.dts) 的 `vcc_lcd_mipi` 节点及 panel 节点给出了这条关系。下面是原文件中抽出的关键属性，不是可独立编译的设备树：

```dts
/* 电源开关使用 GPIO1_D5，物理高电平使能。 */
gpio = <&gpio1 RK_PD5 GPIO_ACTIVE_HIGH>;
enable-active-high;
pinctrl-0 = <&vcc_mipi_pin>;

/* panel 通过引用取得这路电源。 */
power-supply = <&vcc_lcd_mipi>;
```

`vcc_mipi_pin` 在文件第 475–476 行把 GPIO1_D5 选成普通 GPIO；`gpio` 告诉电源驱动控制哪根线；panel 第 125 行的 `power-supply` 则告诉消费者向谁申请电源。它们分别表达管脚功能、控制资源和使用关系，缺一项都可能使软件描述与接线脱节。

核心板的上游电源也按这种关系描述。[CM3 DTSI](../../src/rk3566-radxa-cm3.dtsi) 第 22–49 行定义系统电源，第 125–176 行描述 I2C0 上的 CPU 电源器件和 RK817，第 207 行起描述其电源输出。面板这一小段最终接入更大的供电关系，而不是由一个应用直接给 GPIO 写值后就完成全部初始化。

## 3.3 从使能请求到电压稳定的条件

### 3.3.1 逻辑有效、物理电平与电源输出

软件中的“1”常表示请求有效，示波器看到的高低电平才是物理结果。GPIO 描述符接口可按低有效标志，把逻辑 1 转换成物理低；原始电平接口及某些旧整数 GPIO 用法又有不同约定。因此阅读驱动时，应同时确认使用的 API、设备树极性和实际电路。[Linux GPIO 消费者接口说明](https://www.kernel.org/doc/html/v6.1/driver-api/gpio/consumer.html)

触摸供电恰好提供一个需要三者一起看的例子。旧图第 3 页中，GPIO3_D0 经 Q3 NPN 控制 Q1 P-MOS，连接方法与面板电源类似：物理高电平请求接通 `VCC3.3TP`。但 overlay 的 `vcc_lcd_tp` 第 40–52 行同时写了 `GPIO_ACTIVE_LOW` 和 `enable-active-high`。

不能只挑其中一个字样就断定触摸一定断电。`regulator-fixed` 有自己的极性约定，`enable-active-high` 用于说明高有效；目标 BSP 对旧 GPIO 属性的兼容解析仍须结合实际驱动确认。[Linux 6.1 fixed-regulator 绑定](https://raw.githubusercontent.com/torvalds/linux/v6.1/Documentation/devicetree/bindings/regulator/fixed-regulator.yaml)

当前可以确认的是：**源码里存在需要结合驱动解释的极性组合，原理图要求控制线物理高时接通供电。** 要判断当前系统是否错误，下一步应核对运行树、对应 fixed-regulator 实现和 GPIO3_D0 的实际电平。没有这些证据，不能把静态疑点写成已经发生的触摸故障。

面板复位也服从同样的逻辑。overlay 第 126 行声明 GPIO3_C1 低有效，这表达“复位有效时的电平”。若驱动采用描述符 API，代码中的置 1 可能是在拉低复位线，而不是释放复位。具体哪个调用负责断言或释放，需要读匹配的 panel 实现。

### 3.3.2 电源、复位和等待按硬件阶段接力

电源开关打开后，电压还需要上升并稳定；芯片也需要在适当的复位条件下启动，随后才有条件接受命令。驱动不能把“申请电源成功”直接等同于“器件现在可以通信”。等待时间必须落在它要保护的硬件阶段，挪到另一个阶段后，即使总时长相同也不保证等效。

overlay 为 panel 配置了 `prepare-delay-ms`、`reset-delay-ms`、`init-delay-ms` 和命令序列。当前目录缺少完整配套 panel 驱动，因此能确认配置值及其设计用途，不能补造目标 BSP 的函数顺序或已测得的复位波形。第 6 章继续将这些阶段与初始化命令对应。

`regulator-boot-on` 表达启动阶段应已开启、必要时由系统开启的约定，但不禁止以后关闭；`regulator-always-on` 才声明这路电源不应被关闭。前者解决接管启动状态的问题，后者限制运行期关电，两者不能互相替代。[上游 regulator 属性约定](https://raw.githubusercontent.com/torvalds/linux/v6.1/Documentation/devicetree/bindings/regulator/regulator.yaml)

这些属性不会测量实际电压。框架管理消费者和使用状态，物理电源是否欠压、开关是否损坏，仍需要电气证据。使能操作成功之后，驱动下一步能否通信还依赖电压稳定以及复位释放时序成立。

## 3.4 供电正确后，信号还要走到正确的控制器

### 3.4.1 复用选择决定一根脚正在做什么

RK3566 的管脚可以连接不同内部功能。GPIO1_D5 是管脚身份，pinmux 是“此刻把它接到哪个功能”的选择，pinctrl 则负责描述这类选择及上下拉。设备节点中的 `gpio`、`pwms` 或 I2C 总线位置说明驱动要使用什么资源；两层必须一致。

当前 [IO 板 DTS](../../src/rk3566-radxa-cm3-io.dts) 第 173–185 行开启 SDMMC0 并选择四位数据总线，其中包含 GPIO1_D5；产品 overlay 又把该脚作为面板供电控制。若最终设备树同时保留这两种用途，两者就不能独立使用同一脚。原理图网名中保留的 `SDMMC0_D0` 和 `MIPI_EN`，也提示这是两种不同用途。

这一风险有明确条件：它针对同时启用两个消费者的最终组合。现有交付包的基础 DTB 已禁用 SDMMC0，所以不能把本地源文件中的组合直接当作包内系统的实际冲突。第 2、10 章分别说明包的身份和运行树的检查方式。

### 3.4.2 同一网名到了另一块板上，负载可能已经变了

3 页相机底板第 1 页沿用了部分网名，但 GPIO3_C1 接绿色 LED 驱动，GPIO3_B4 接红色 LED 驱动，GPIO3_C2 接蓝色 LED 驱动。地面站 overlay 用前两者作面板复位和外部供电检测，IO DTS 第 30–39 行则把 GPIO3_C2 用作 USB 5 V 电源使能。

| 管脚 | 地面站软件声明 | 相机底板图的负载 | 配套检查的重点 |
| --- | --- | --- | --- |
| GPIO3_C1 | panel 复位 | 绿色 LED | 操作是否真的到达面板复位端 |
| GPIO3_B4 | 外部电源输入检测 | 红色 LED 驱动 | 输入检测模型是否对应实际电路 |
| GPIO3_C2 | USB 电源使能 | 蓝色 LED | 软件开启的是哪一个物理负载 |

因此选资料时应先看板型与连接对象，再看文件日期。日期较新的文件并不自动覆盖其他硬件方案；网名写着 `MIPI_RST` 也不替代实际追线。

### 3.4.3 电压域和上拉决定通信的电气前提

I2C 器件通过拉低总线传递状态，释放后由上拉电阻形成高电平。因此“芯片供电电压”和“SDA/SCL 高电平来自哪路电源”要分别确认。控制器选对了，但上拉电压不合适或器件仍在复位，也可能没有有效应答。

CM3 DTSI 第 113–123 行为不同 IO 电压域指定了 1.8 V 或 3.3 V 供电，不能把所有 GPIO 都当成固定 3.3 V。旧底板第 3 页中，触摸 SDA/SCL 上拉到 `VCC3.3CW`，芯片供电却由 `VCC3.3TP` 控制。关闭后者不意味着前者同时消失；器件断电时是否容许总线仍为高，需要配套芯片规格与实物确认。

这些约束解释了 regulator、pinctrl 和总线驱动为什么要分工：电源提供可工作条件，引脚选择物理通路，总线执行通信。分工能复用驱动，但描述不一致时会表现为资源申请失败、延后探测或没有应答，排查也必须沿同样的依赖顺序进行。

## 3.5 把其他外设放回同一套硬件关系

理解了面板电源的追踪方法，再看下表就不是背引脚，而是在比较每种外设需要什么通道。对象仍限定为 8 页底板方案及当前产品 overlay。

| 功能 | 原理图通路 | 设备树对应位置 | 交给后续章节的作用 |
| --- | --- | --- | --- |
| 面板像素 | 第 3 页 DSI 时钟、四组差分数据到屏幕 FPC | `dsi0`、`video_phy0`、panel endpoint | 发送命令和像素 |
| 面板供电/复位 | GPIO1_D5 经 Q4/Q2；GPIO3_C1 经 R29 到 FPC | `vcc_lcd_mipi`、`reset-gpios` | 建立面板启动条件 |
| 触摸供电 | GPIO3_D0 经 Q3/Q1 到 `VCC3.3TP` | `vcc_lcd_tp` | 建立触摸通信前提 |
| 触摸通信与通知 | U7 的 GPIO0_B4/B3、GPIO0_C5/C6 | `i2c1`、`gt9xx@14`、中断/复位属性 | 读取触点，处理通知和启动 |
| 背光调光 | GPIO0_C4 经光耦到 SY7201 EN/PWM | PWM5，周期 50000 ns | 调整背光有效驱动比例 |
| 背光电源 | GPIO4_B3 经 Q6/Q9 | `enable-gpios` | 开关升压电路的输入供电 |
| 电量计 | 第 4 页 U8 CW2015，SDA/SCL 到 GPIO1_A0/A1 | `i2c3m0_xfer`、`cw2015@62` | 读取电池测量与估计状态 |
| 外部电源检测 | 9 V 经 U23 光耦到 GPIO3_B4 | `gpio-charger` | 报告外部供电在线状态 |
| 风扇 | 第 8 页 PWM0_M1 经 R81/U31 到 CN1 | `pwm0m1_pins`、`fan0` | 接受温控选择的冷却强度 |

对应源件是 [AIRCAS overlay](../../设备树包/aircas-compact-GCS_overlay.dts) 和 [IO DTS](../../src/rk3566-radxa-cm3-io.dts)。其中 PWM0_M1 与 GPIO0_C7 的关联可在交付 DTB 中查到；本目录未保存完整 SoC pinctrl 源码，第 9 章给出包内定位。

## 3.6 怎样把硬件推导变成可复核的检查

本章确认的是源码声明、包内差异和原理图设计。实际贴装、波形和负载效果仍是待确认事项。后续板端检查可以按下面三步取得不同层次的证据，本次没有执行这些测量。

1. **先确认对象。** 记录核心板、底板丝印、屏幕型号和实装器件，选择对应图纸。这一步决定后续应该追哪一组引脚，不能证明电路已经正常。
2. **再确认路径。** 断电后沿连接器、网名、中间器件和核心板脚位核对，留意改线及 NC/实装电阻。它能排除板型或连接差异，不能替代上电时序。
3. **最后对照控制与响应。** 在适当测量条件下比较 GPIO、受控电源、复位和总线。GPIO 正确而电源不起，继续查开关与上游供电；电源稳定而 I2C 无应答，转查复位、地址、上拉和 pinmux；通信形成有效数据后，再进入驱动协议判断。

控制与响应要分别记录。比如 regulator 显示 enabled，说明框架或提供者报告了使能状态，未必包含外设端电压测量；测点电压满足要求才证明这一段电路响应。再结合复位和总线，才能解释驱动下一步是否具备通信条件。

## 3.7 自查问题

1. 屏幕背光亮、触摸也有事件，但没有图像，为什么不能据此证明 DSI 和面板初始化正常？
2. GPIO3_D0 的逻辑使能值、物理高电平和 `VCC3.3TP` 输出电压分别由什么决定？
3. 发现 GPIO1_D5 同时出现在 SDMMC0 和屏幕供电配置中，接下来应查哪份描述？
4. 用 regulator 表达供电，比应用直接写 GPIO 多解决了什么问题，又增加了什么适配责任？

## 3.8 回答要点

1. 背光、触摸、像素传输走不同硬件通道。已有结果只支持对应链路；还需分别确认面板逻辑供电、复位、命令与 DSI 像素输出。
2. 逻辑值先经过 GPIO API 和极性规则解释，再形成管脚电平；管脚经 NPN/P-MOS 控制电源，最终电压还取决于供电与器件。任一层都不能凭上一层的状态代替测量。
3. 先确认实物，然后查实际加载并合成后的设备树及 pinctrl 归属。当前源 DTS 和包内 DTB 的 SDMMC0 状态不同，单看某一文件不够。
4. regulator 统一管理供电提供者、消费者与使用状态，使器件驱动不必写死底板开关。适配者仍要准确描述引用、极性、时序和错误条件；框架不代替电气验证。
