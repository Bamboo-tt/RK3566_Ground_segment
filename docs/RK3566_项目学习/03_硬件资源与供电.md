# 03 硬件资源与供电：先确认软件正在控制哪根线

上一章把内核、DTB 和 DTBO 放回了构建与交付体系。本章把视线移到它们要描述的实体：CM3 核心板提供计算和控制器，自定义底板把控制器引出，并提供连接器、供电开关和电平转换。下一章再将这里得到的连接关系写成设备树依赖。

板级适配的起点是“某个器件需要哪路电源、连接到哪个控制器、控制信号经过什么电路”，不是先寻找一个能填写的 GPIO 编号。**同一根 SoC 引脚可以承担不同复用功能，同一份网名也可能在不同底板上被沿用。**

## 3.1 先分清核心板、底板与屏幕组件

CM3 是承载 RK3566 及其配套存储、供电等基础资源的核心模块；本项目中的自定义底板负责把模块接口接到具体外设。软件中也有对应边界：[`rk3566-radxa-cm3.dtsi`](../../src/rk3566-radxa-cm3.dtsi) 描述模块资源和供电关系，IO 板 DTS 与产品 overlay 进一步选择外设和引脚。

**源码事实：** CM3 DTSI 第 22–49 行描述系统 5 V、3.3 V 电源关系，第 125–176 行描述 I2C0 上的 CPU 电源器件和 RK817 电源管理芯片，第 207 行起描述各路 regulator。这里的 regulator 是 Linux 对电源提供者的抽象：消费者申请“开启我的供电”，由电源驱动完成 GPIO 或寄存器操作。

**资料记录：** [`较早底板原理图`](../../原理图/SCH_RK3566底板V2_2025-10-21.pdf) 共 8 页，其中第 3 页是 MIPI 屏幕，第 4 页是电池管理，第 8 页是风扇。它能支撑本章的屏幕、电量和风扇电路分析。根目录 [`另一份底板原理图`](../../SCH_RK3566底板V2_2025-11-21.pdf) 共 3 页，图内标识为 `3566cam_internet`，有相机 FPC、网络和指示灯；不能仅凭文件日期把它当成前一份地面站底板的无条件替代品。

| 对象 | 本章能够确认的职责 | 不能据此推导的结果 |
| --- | --- | --- |
| CM3 核心板 | 提供 SoC 控制器、模块供电与基础总线资源 | 某台实板的模块 SKU、所有器件实际贴装和运行状态 |
| 8 页底板方案 | 屏幕/触摸供电、背光驱动、电量采样、充电电路、风扇接口 | 所有版本底板都沿用这套接线 |
| 3 页相机底板方案 | 相机、网络、指示灯及其他接口连接 | 已实现地面站显示、触摸和电池系统 |
| 7 英寸屏幕资料 | 800×1280 屏幕与 ILI9881C/GT9XX 适配材料 | 所有 GT9XX 驱动与配置可互换 |
| 6 英寸屏幕资料 | 另一套面板、初始化序列和触摸适配记录 | 可直接使用 7 英寸时序、profile 和坐标变换 |

屏幕组件必须拆成三条链路：DSI 传送像素和面板命令，I2C 加中断传送触摸数据，PWM 加使能信号控制背光。触摸可工作而屏幕无图像，背光可亮而 DSI 尚未建立，这些都不矛盾。

## 3.2 沿连接器追到控制器，而不是跳过中间电路

以下映射以 **8 页底板方案及当前 AIRCAS overlay** 为对象。原理图证明设计连接，源码证明软件声明；二者同时存在仍不等于实板已正确贴装。

| 功能 | 原理图中的连接与中间电路 | 软件入口 | 资源作用 |
| --- | --- | --- | --- |
| 面板像素 | 第 3 页屏幕 FPC 的 DSI 时钟和四组数据差分对 | `dsi0`、`video_phy0`、panel endpoint | 高频串行像素与面板命令通道 |
| 面板供电 | `GPIO1_D5` → Q4 NPN → Q2 P-MOS → `VCC_LCD_MIPI` | `vcc_lcd_mipi`，overlay 第 26–38 行 | 控制面板逻辑电源 |
| 面板复位 | `GPIO3_C1_MIPI_RST` 经 R29 接 FPC | panel 的 `reset-gpios`，第 126 行 | 让面板进入/退出复位状态 |
| 触摸供电 | `GPIO3_D0` → Q3 NPN → Q1 P-MOS → `VCC3.3TP` | `vcc_lcd_tp`，第 40–52 行 | 控制触摸芯片电源 |
| 触摸通信 | U7 FPC 的 SDA/SCL，网名含 GPIO0_B4/B3 | `i2c1`、`gt9xx@14`，第 391–410 行 | 读取配置、状态和触点 |
| 触摸中断/复位 | GPIO0_C5 / GPIO0_C6 接 U7 | `touch-gpio` / `reset-gpio` | 中断通知数据就绪；复位参与芯片启动 |
| 背光调光 | GPIO0_C4 → 光耦 → SY7201 的 EN/PWM | `pwm5`、`pwms`，第 59 行 | 改变背光有效驱动比例 |
| 背光供电使能 | GPIO4_B3 → Q6 NPN → Q9 P-MOS | `enable-gpios`，第 60 行 | 开关背光升压电路的输入电源 |
| 电量计 | 第 4 页 U8 CW2015，SDA/SCL 接 GPIO1_A0/A1 | `i2c3m0_xfer`、`cw2015@62` | 电池电压与电量状态采集 |
| 外部电源检测 | 9 V → U23 光耦 → GPIO3_B4 | `gpio-charger`，第 105–111 行 | 感知外部供电是否存在 |
| 风扇 | 第 8 页 `PWM0_M1` → R81、U31 AO3400 → CN1 | IO DTS 的 `pwm0m1_pins`、`fan0` | 调节二线风扇供电路径 |

源文件位置见 [`AIRCAS overlay`](../../设备树包/aircas-compact-GCS_overlay.dts) 和 [`IO 板 DTS`](../../src/rk3566-radxa-cm3-io.dts)。GPIO0_C7 对应 PWM0_M1 的关联还需结合被包含的 SoC pinctrl 定义；本目录缺少该定义的完整源码，包内 DTB 和构建记录可作为补充，见第 9 章。

### 一条信号的完整追踪示例

以面板供电为例，先在第 3 页 FPC 找到 `VCC_LCD_MIPI`，逆向追到 Q2，再追到 Q4 基极及 `SDMMC0_D0_MIPI_EN_GPIO1_D5`。这说明软件并非直接给面板供电，而是用 GPIO 控制晶体管级联的电源开关。

在 overlay 中找到 `gpio = <&gpio1 RK_PD5 GPIO_ACTIVE_HIGH>` 和 `pinctrl-0 = <&vcc_mipi_pin>`；后者在第 475–476 行把该脚选为 GPIO。panel 的 `power-supply = <&vcc_lcd_mipi>` 将消费者连接到电源提供者。驱动申请 panel 电源时，regulator 框架才能沿这个引用找到开关控制。

这条追踪给出的下一章输入是：**资源身份、控制方向、有效极性、上游供电、消费者关系** 。缺任何一项，都可能出现“节点成功绑定，但硬件没有响应”。

## 3.3 电源开关为什么需要同时理解逻辑和物理

### GPIO 高低、有效状态和电源输出是三个概念

**通用原理：** GPIO 描述符接口的逻辑 `1` 表示“有效”。当描述符为低有效时，它可转换成引脚上的物理低电平；使用原始电平接口或旧整数 GPIO API 时又可能不同。因此，不能看到函数参数 `1` 就直接解释为 3.3 V。[Linux GPIO 消费者接口说明](https://www.kernel.org/doc/html/v6.1/driver-api/gpio/consumer.html)

**资料记录与电路推导：** 在旧底板第 3 页，GPIO3_D0 物理拉高使 Q3 NPN 导通，进而拉低 Q1 P-MOS 的栅极；当栅源电压满足导通条件时，输入 3.3 V 接到 `VCC3.3TP`。GPIO 拉低时，NPN 关断，P-MOS 栅极被上拉。面板供电 Q4/Q2 使用同类电路。因此这套电路的外部控制含义是“GPIO 物理高时请求接通”。这只是原理图推导，器件贴装、旁路电阻和实际波形仍需确认。

**源码事实：** `vcc_lcd_tp` 同时写了 `GPIO_ACTIVE_LOW` 和 `enable-active-high`。两种文字不能各自独立解释后再任意选择一个。`regulator-fixed` 的专用绑定以 `enable-active-high` 表达使能极性；目标 BSP 中 GPIO 兼容处理和驱动版本决定最终解析行为。[Linux 6.1 fixed-regulator 绑定](https://raw.githubusercontent.com/torvalds/linux/v6.1/Documentation/devicetree/bindings/regulator/fixed-regulator.yaml)

**待确认事项：** 应检查实际绑定的 fixed-regulator 实现、运行设备树和 GPIO 物理电平，再判断这组声明是否产生错误。当前只证明源码存在容易误读的极性组合，不能写成“触摸供电必然反了”或“已经现场故障”。

### 开启电源后为什么仍需复位和等待

电源输出上升需要时间，芯片内部状态也需要稳定。电源开启、保持复位、释放复位、等待内部启动、开始总线通信，是不同操作。等待必须放在对应硬件阶段，单纯把总等待时间凑够没有相同效果。

overlay 为 panel 声明了 `prepare-delay-ms`、`reset-delay-ms`、`init-delay-ms` 等值，并单独定义命令序列。它们由驱动解析，具体调用顺序必须回到配套 panel 驱动确认。这里缺少该驱动完整源码，因此本章只确认这些配置存在，不能拼出项目已验证的复位波形。第 6 章进一步分析命令等待位置。

`regulator-boot-on` 表达启动阶段供电状态的约定；它不证明电压已达到规格。`regulator-always-on` 限制软件关闭该电源，也不替代短路、欠压或器件失效检测。软件引用计数只管理“哪些消费者需要供电”，不会测量每个消费者是否真的得到电。

## 3.4 引脚复用冲突必须结合最终设备树和板型判断

同一 GPIO 的数字编号只代表 SoC 管脚身份，pinmux 决定它此时连向 GPIO、PWM、I2C 或其他内部功能。`pinctrl` 负责选功能及上下拉；`gpio`、`pwms` 等属性则让设备驱动申请已经描述好的资源。这两层一致才有意义。

### GPIO1_D5：屏幕供电与 SDMMC0 数据线

**源码事实：** 当前 IO DTS 第 173–185 行开启 `sdmmc0` 并选择 `sdmmc0_bus4`；overlay 用 GPIO1_D5 控制屏幕供电。旧图第 3 页网名本身就保留了 `SDMMC0_D0` 与 `MIPI_EN` 两种用途。

这构成条件性冲突：如果最终 DT 同时启用占用该脚的 SDMMC0 四位总线与面板 GPIO 控制，两者不能同时独立驱动同一引脚。应核查最终合成 DT，而非只看某个文件中的 `status`。交付包内基础 DTB 的具体状态见第 2、10 章；不能把源文件冲突直接移植成包内系统已冲突的结论。

### 相同网名出现在另一底板时，必须重新追线

**资料记录：** 3 页相机底板第 1 页中的 GPIO3_C1 接绿色 LED 驱动，GPIO3_B4 接红色 LED 驱动，GPIO3_C2 接蓝色 LED 驱动。某些网名仍带 `MIPI_RST` 或 `9V_IN`，但连接对象已变。

| 管脚 | 地面站资料中的软件用途 | 相机底板图中的用途 | 误套配置的影响范围 |
| --- | --- | --- | --- |
| GPIO3_C1 | panel 复位 | 绿色 LED | 复位操作可能只改变指示灯 |
| GPIO3_B4 | 外部 9 V 在线输入 | 红色 LED 驱动 | 检测输入模型与输出电路不再对应 |
| GPIO3_C2 | IO DTS 的 USB 5 V regulator 使能 | 蓝色 LED | 软件电源使能语义与实物负载不一致 |

这不是判定哪个文件“过时”，而是确认它们描述不同硬件对象。实际使用哪块底板、是否改线和哪份软件与它配套，是继续部署前的必要输入。

## 3.5 电压域、上拉和供电依赖决定“能不能通信”

I2C 由器件共同拉低总线，上拉电源决定总线高电平。设备有电但 SDA/SCL 上拉到错误电压域，或者控制器脚尚未切为 I2C，都可能没有有效通信。复位脚和中断脚也要与器件 IO 电压兼容。

**源码事实：** CM3 DTSI 第 113–123 行声明多个 IO 电压域，其中有 1.8 V 和 3.3 V 供电；这说明不能把整个 SoC 的 GPIO 都当成固定 3.3 V。**资料记录：** 旧图第 3 页触摸 SDA/SCL 上拉到 `VCC3.3CW`，而触摸芯片供电由 `VCC3.3TP` 控制。关闭触摸电源后，上拉电源未必同时消失；断电器件是否允许该状态，需要器件手册和实物确认。

这也是采用 regulator、pinctrl 和总线驱动分工的原因：驱动能按资源依赖申请供电、引脚和控制器，而不是把电源开关散落在用户程序中。代价是资源描述必须准确，错误可能表现为延后探测、资源忙或没有应答，需要沿依赖链定位。

## 3.6 用三步检查建立硬件证据

以下是待执行的核验方法，本次只读资料，未测量实板。

1. **确认对象。** 记录底板丝印、核心板版本、屏幕型号和实际贴装，逐项对照原理图。它证明正在分析的材料是否对应当前硬件，不能证明电气工作正常。
2. **确认路径。** 在断电条件下依据原理图核连接器到网名、控制器和中间电路，核查改线、NC/实装电阻。它排除接错板型和连接路径，不能代替上电时序与电平测量。
3. **确认效果。** 在适当测量条件下同步观察控制 GPIO、受控电源、复位及总线信号。GPIO 电平正确但电源不起，应继续查开关和供电；电源稳定但 I2C 无应答，应查复位、地址、上拉和 pinmux；总线可通信再进入驱动协议层。

关键判断是把“控制命令发出”和“被控对象响应”分别记录。例如 regulator 显示 enabled 只说明软件状态；板上电源测点达到要求才补上物理证据。

## 3.7 自查：能否从接线讲到软件资源

**问：为什么不能用一个“屏幕驱动”概括显示、触摸和背光？**
回答要点：三者分别使用 DSI、I2C/IRQ、PWM/GPIO，数据方向、执行上下文和标准接口不同。任一链路成功都不能替另外两条验收。

**问：GPIO3_D0 拉高、regulator 使能、触摸芯片有电是否等价？**
回答要点：逻辑有效值要经过驱动极性解释；物理电平经过晶体管才改变电源；电压稳定还依赖上游供电和器件。每层应有独立依据。

**问：GPIO1_D5 的潜在冲突应在哪一层决定是否成立？**
回答要点：先核实板接线，再看最终 DT 中 SDMMC0 和屏幕供电消费者是否同时启用，最后检查 pinctrl 实际归属；单份 overlay 或基础源码均不充分。

**问：使用 regulator 框架比应用直接写 GPIO 多了什么，付出什么代价？**
回答要点：增加供电依赖、消费者管理和电源状态协作；代价是要正确描述供电与极性，并处理提供者未就绪等错误。抽象不能替代电气测量。
