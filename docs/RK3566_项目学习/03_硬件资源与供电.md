# 03 硬件资源与供电：把连接、控制与供电对应起来

```text
资源依赖视角
CM3 核心板                         自定义底板                    外设
  控制器与管脚 ───连接器──────→ 复用信号、保护与转换 ───────→ 数据/控制端
  上游电源 ──────────────────→ 电源轨与负载开关 ───────────→ 电源端
                                      ↑
                               GPIO 使能控制开关

面板路径展开
GPIO3_C1 → J3-97 → GPIO3_C1_MIPI_RST → R29 → FPC1-27 → 面板复位
GPIO1_D5 → Q4 → Q2 栅极（控制开关）
                    ↓
VCC3.3CW ──────────→ Q2 ──→ VCC_LCD_MIPI → FPC1-30/31 → 面板供电

这些连接 → pinctrl、GPIO、regulator 和总线资源描述 → 驱动取得工作条件
```

核心资料是 [8 页地面站底板图](../../原理图/SCH_RK3566底板V2_2025-10-21.pdf)第 1、3、4、8 页、[CM3 DTSI](../../src/rk3566-radxa-cm3.dtsi)、[IO 板 DTS](../../src/rk3566-radxa-cm3-io.dts)和 [AIRCAS overlay](../../设备树包/aircas-compact-GCS_overlay.dts)的电源、pinctrl 与外设节点。根目录的 [3 页底板图](../../SCH_RK3566底板V2_2025-11-21.pdf)图内名称为 `3566cam_internet`，在 3.5 节单独比较。

[上一章](02_BSP构建与交付.md)已经把内核、DTB、DTBO 与系统文件分开。现在回到这些产物控制的对象：一根管脚上的电平，怎样变成面板复位、负载供电或总线通信？先理解这次电气交接，下一章才能准确地把它写成设备树资源。

## 3.1 核心板提供能力，底板决定能力接到哪里

CM3 集成 RK3566、存储和核心供电等资源，通过板间连接器引出显示、I2C、GPIO、PWM、USB 等接口。底板连接屏幕、电池、风扇及扩展接口，并加入电源开关、上拉、保护和信号转换。驱动的工作条件，同时来自核心板的控制器和底板的实际接线。

屏幕组件包含几条不同通道：液晶面板经 DSI 接收命令和像素，背光电路经 PWM 调整照明，触摸控制器经 I2C 返回触点、用 INT 通知处理器。它们可装在同一模组中，却有独立电源和控制通道。触摸能读出坐标时，排查无图像仍要进入 DSI 和面板状态；背光发光时，仍要看液晶是否接收了正确像素。

8 页底板图第 3 页中，FPC1 接面板与 LED，U7 接触摸；Q2/Q4 开关面板逻辑电源，Q1/Q3 开关触摸电源，Q9/Q6 开关背光电源，U5 处理背光 PWM 信号。下文沿这份设计追踪，6 英寸云奥与 7 英寸阿美林的器件配置在后续章节分别解释。

## 3.2 从连接器的一根复位线追到 SoC

### 3.2.1 跨页网络把外设连接到核心板

先在第 3 页找到 FPC1 的 **27 脚**。它经过 0 Ω 电阻 R29 接到 `GPIO3_C1_MIPI_RST`，连接器侧还有 R30 的 10 kΩ 下拉。回到第 1 页，同名网络接到 CM3 板间连接器 **J3 的 97 脚**，对应 RK3566 的 GPIO3_C1。跨页网名把同一个电气节点连接起来，R29 则标出了串接和装配位置。

软件从另一端表达这条连接：overlay 的 `dsi0_lcd_rst_gpio` 将 GPIO3_C1 交给 pinctrl，要求它使用 GPIO 功能；`panel@0` 的 `reset-gpios` 再把这根线交给面板驱动。GPIO3_C1 是 SoC 管脚身份，J3-97 和 FPC1-27 是两只连接器的脚号，Linux 运行时 GPIO/IRQ 编号又是另一套编号。分开这些编号，才能沿排线和测点找到软件操作的位置。

### 3.2.2 pinctrl 选择功能，GPIO 改变状态

管脚复用决定一根脚接到 SoC 内部哪个功能。选择 GPIO 后，GPIO 控制器可改变方向和电平；若选择其他外设复用功能，驱动知道 GPIO 编号也未必能按预期驱动管脚。pinctrl 还可指定上拉、下拉，它与外部 R30 是分别存在的电路条件。

下面摘录 overlay 的复位描述，省略其他 panel 属性：

```dts
/* panel 消费者：低电平表示复位有效。 */
reset-gpios = <&gpio3 RK_PC1 GPIO_ACTIVE_LOW>;
pinctrl-names = "default";
pinctrl-0 = <&dsi0_lcd_rst_gpio>;

/* pinctrl 状态：让 GPIO3_C1 采用 GPIO 功能。 */
dsi0_lcd_rst_gpio: dsi0-lcd-rst-gpio {
    rockchip,pins = <3 RK_PC1 RK_FUNC_GPIO &pcfg_pull_none>;
};
```

复位线控制芯片是否处于复位状态；面板持续供电走 FPC1 的 30、31 脚，来自 `VCC_LCD_MIPI`。即使复位脚释放为高，只要逻辑电源尚未建立，芯片仍无法正常接收 DSI 命令。

## 3.3 GPIO 怎样控制一条电源轨

### 3.3.1 负载电流经过 MOS，GPIO 控制其栅极

第 3 页的面板供电路径为 `VCC3.3CW → Q2 → VCC_LCD_MIPI`。Q2 是 AO3401A P 沟道 MOS；GPIO1_D5 经 R23 驱动 NPN 三极管 Q4，再经 R21 影响 Q2 栅极。负载电流与控制电流走两条支路，GPIO 无需直接提供面板工作电流。

GPIO1_D5 为高时，Q4 导通并拉低 Q2 栅极；Q2 源极位于 3.3 V 输入端，`VGS = VG − VS` 变负，开关接通。GPIO 为低时，Q4 关断，R19 把栅极拉回源极附近，Q2 关闭。R17 标为 NC，是跨过 Q2 的可选旁路；若实际装配将它短接，软件关断 Q2 也无法切断旁路供电。

用图中电阻计算导通时的控制条件：假设输入为 3.3 V，Q4 饱和压降约 0.2 V，忽略 MOS 栅极直流电流，R19=100 kΩ、R21=10 kΩ。

```text
栅极控制支路电流 ≈ (3.3 − 0.2) V / (100 + 10) kΩ ≈ 28.2 µA
VG ≈ 0.2 V + 28.2 µA × 10 kΩ ≈ 0.482 V
VGS ≈ 0.482 − 3.3 = −2.82 V
```

栅极电压由电阻和 Q4 共同决定，GPIO 高电平并未直接加到 MOS 栅极。面板端电压还受上游电压、Q2 导通电阻、走线压降和负载电流影响；控制信号成立与负载供电满足要求，是相邻的两个判断。

### 3.3.2 regulator 把电源开关交给统一的提供者

面板驱动需要表达“启用我的电源”，无需写死 Q2/Q4 的连接。Linux 用 regulator 表示电源提供者，面板通过供电引用成为消费者。overlay 中的对应关系如下，属于原节点摘录：

```dts
vcc_lcd_mipi: vcc-lcd-mipi {
    compatible = "regulator-fixed";    /* 固定电压电源，由 GPIO 控制开关 */
    regulator-name = "vcc_lcd_mipi";
    pinctrl-names = "default";
    pinctrl-0 = <&vcc_mipi_pin>;         /* GPIO1_D5 采用 GPIO 功能 */
    gpio = <&gpio1 RK_PD5 GPIO_ACTIVE_HIGH>;
    enable-active-high;                /* 开关使能对应物理高电平 */
    regulator-boot-on;                  /* 接管启动阶段预期已开启的电源 */
    /* 省略 status 和休眠约束。 */
};

/* panel@0 中的消费者引用，获取资源时使用名称 "power"。 */
power-supply = <&vcc_lcd_mipi>;
```

pinctrl 选择管脚功能，fixed regulator 持有开关控制线，panel 通过 `power-supply` 请求电源。`regulator_enable()` 成功表示框架完成了所需使能操作；该开关没有输出电压反馈，电气故障要从 Q2 前后测点继续定位。

核心板供电也采用同一模型。CM3 DTSI 的 `vcc_sys/vcc3v3_sys/vcc5v0_sys` 描述系统电源，I2C0 上的 `tcs4525@1c` 和 `rk817` 提供 CPU 及其他电源输出。消费者引用表达依赖，驱动按照依赖取得资源，不按 DTS 节点的文字顺序依次上电。

### 3.3.3 逻辑有效值先由驱动解释，再经过外部电路

GPIO descriptor 的逻辑接口用 1 表示有效、0 表示无效。面板复位配置为低有效，所以 `gpiod_direction_output(reset, 1)` 输出低电平以断言复位，置 0 才释放为高。旧整数 GPIO 的 `gpio_direction_output()` 直接使用电平值，两类代码应分别解释。

触摸电源有一处容易误读的配置：`vcc_lcd_tp` 同时写 `GPIO_ACTIVE_LOW` 和 `enable-active-high`。历史构建记录指定的 [Radxa 基线 gpiolib-of.c](https://github.com/radxa/kernel/blob/3bbac32c942f4d98fc87bde3852f185dce56ff56/drivers/gpio/gpiolib-of.c)中，`of_gpio_flags_quirks()` 对 `regulator-fixed` 专门按 `enable-active-high` 决定极性；出现上述组合时会警告并清除低有效标志。因此这套处理得到的是**物理高电平使能**，与 GPIO3_D0 经 Q3/Q1 接通 `VCC3.3TP` 的电路一致。

这是特定 regulator 绑定的兼容处理，不能推广到所有 `*-gpios` 属性。将同样配置移到没有该处理的驱动，或仅按 GPIO 属性末尾的数值解释高低，结果就会不同。

## 3.4 电源建立之后，还需要复位、时钟和总线条件

### 3.4.1 等待必须约束相邻硬件事件

开关导通后，电源需要给电容和负载充电；芯片还要完成复位并进入可通信状态。供电、断言复位、释放复位和第一次命令之间的间隔各有用途，总等待时间相同并不意味着可以互换位置。[第 6 章](06_显示与背光.md)将 `prepare/reset/init` 延迟放回具体 panel 回调，展示它们分别位于哪两个动作之间。

`regulator-boot-on` 描述启动接管时预期电源已开，也允许驱动在需要时将它开启；`regulator-always-on` 进一步禁止正常运行中的关断。前者不等同于永久开启。消费者共享电源时，框架管理使用关系，某个消费者释放自己的使能请求后，电源可能仍被其他消费者使用。

控制器自身还有时钟和复位资源。DSI Host 需要寄存器访问时钟、协议时钟与 PHY，I2C 控制器需要控制器时钟，这些资源主要来自 SoC 基础描述。板上的面板 RST 与 SoC 内部控制器 reset 是两个对象：前者接到外部芯片，后者复位 SoC 内部模块。控制器就绪后，驱动才有条件发起总线事务。

### 3.4.2 电压域和上拉决定信号是否有效

CM3 DTSI 的 `pmu_io_domains` 将各组 IO 电压域连接到对应电源，其中既有 1.8 V，也有 3.3 V。引脚号本身不表示固定电压。外部器件输入容限、上拉电源和核心板电压域需要配套，才能把软件高低值可靠地转换成电气高低值。

I2C 通过拉低与释放总线传输，释放后的高电平由上拉产生。旧底板第 3 页的触摸 SCL/SDA 经 R31/R32（各 4.7 kΩ）上拉到 `VCC3.3CW`，触摸芯片供电却由 `VCC3.3TP` 控制。关断触摸电源时，上拉网络仍可能带电；断电器件能否容许这种输入、是否通过保护结构反向供电，要按具体触摸芯片的断电输入要求判断。

定位应沿工作条件推进：控制 GPIO 已切换而负载电源不起，检查上游与开关；电源稳定但 I2C 没有应答，继续看复位、地址选择、上拉及 pinmux；总线返回完整数据后，再进入驱动协议和子系统处理。

## 3.5 同一管脚在不同组合中可能承担不同工作

### 3.5.1 SD 卡与面板开关共享 GPIO1_D5

当前 IO 板 DTS 启用 `sdmmc0` 并选取 `sdmmc0_bus4`，其中 D0 使用 GPIO1_D5；产品 overlay 又把 GPIO1_D5 分配给面板电源。若按当前源码重建并同时保留这两个消费者，同一管脚会被要求承担两种复用功能，可能在 pinctrl 申请时冲突，或使其中一路得不到期望信号。

[交付内核包](../../debs/linux-image-6.1.84-12-rk2410-nocsf_6.1.84-12_arm64.deb)的 `usr/lib/linux-image-6.1.84-12-rk2410-nocsf/rockchip/rk3566-radxa-cm3-io.dtb` 则将 SDMMC0 设为 disabled。使用该基础 DTB 与从当前 IO DTS 重建，是不同的资源组合。处理冲突要看叠加完成的最终树。

### 3.5.2 板型变化后，沿用网名不等于沿用负载

根目录 3 页图的第 1 页仍出现 `GPIO3_C1_MIPI_RST`，但它实际进入绿色 LED 驱动；`GPIO3_B4_9V_IN` 进入红色 LED 驱动，GPIO3_C2 进入蓝色 LED 驱动。相比之下，地面站产品将前两根线用于面板复位和外部电源检测，IO DTS 还将 GPIO3_C2 用作 USB 5 V 开关。

| 管脚 | 地面站方案/对应软件用途 | 3 页相机网络板的实际负载 |
| --- | --- | --- |
| GPIO3_C1 | 面板复位 | 绿色 LED 驱动 |
| GPIO3_B4 | 外部电源输入检测 | 红色 LED 驱动 |
| GPIO3_C2 | IO DTS 的 USB 电源使能 | 蓝色 LED 驱动 |

选择图纸应先对照板型、连接器和负载，日期只帮助区分修订。把地面站 overlay 用到这份相机板上，操作对象已经改变；调整复位延迟无法恢复一条没有接到面板的线路。

## 3.6 将其他外设整理成同一套资源关系

下表仍以 8 页地面站底板为对象，帮助把接线交给后续设备树与驱动章节：

| 功能 | 硬件连接 | 设备树交接 | 后续机制 |
| --- | --- | --- | --- |
| 面板像素 | DSI0 时钟与四组差分数据到 FPC1 | `dsi0`、`video_phy0`、panel endpoint | [第 6 章](06_显示与背光.md)：像素与面板状态 |
| 面板电源/复位 | GPIO1_D5 经 Q4/Q2；GPIO3_C1 经 R29 | `vcc_lcd_mipi`、`reset-gpios` | 上电、复位和初始化命令 |
| 触摸供电 | GPIO3_D0 经 Q3/Q1 到 U7-1 | `vcc_lcd_tp`、`tp-supply` | [第 5 章](05_驱动匹配与初始化.md)：取得资源与选址 |
| 触摸通信/通知 | U7-6/5 为 SCL/SDA，U7-3/4 为 INT/RST | `i2c1`、`gt9xx@14`、GPIO0_C5/C6 | [第 7 章](07_触摸与input.md)：触点采集 |
| 背光调光 | GPIO0_C4 → U5 → SY7201 EN/PWM | `pwm5`、周期 50000 ns、反相极性 | 亮度查表后形成 PWM |
| 背光供电 | GPIO4_B3 经 Q6/Q9 控制输入电源 | backlight 的 `enable-gpios` | 与调光信号分别控制 |
| 电量计 | 第 4 页 U8，GPIO1_A0/A1 为 SDA/SCL | `i2c3m0_xfer`、`cw2015@62` | [第 8 章](08_电量与外部供电.md)：测量与估算 |
| 外部电源检测 | 第 4 页 9 V 经 U23 到 GPIO3_B4 | `gpio-charger` | 在线状态，与充电功率通路分开 |
| 风扇输出 | 第 8 页 PWM0_M1 经 R81/U31 到 CN1 | `pwm0m1_pins`、`fan0` | [第 9 章](09_温控与风扇.md)：冷却档位与输出 |

这些连接决定哪些对象成为节点、哪些控制线需要 pinctrl、哪些消费者引用电源、哪些总线负责通信。软件申请资源之后，还要由对应控制器和电路完成动作，才能得到外设端响应。

## 3.7 核心工程问题与深度理解

### 3.7.1 面板复位脚已经变高，为什么还要测 FPC1 的电源端

复位释放只改变一个控制条件。逻辑电源由 GPIO1_D5 经 Q4/Q2 独立开关，复位由 GPIO3_C1 经 R29 到 FPC1-27。若 Q2 之前没有电，或开关没有导通，复位高电平也无法让未供电的芯片接收命令。应将 FPC1-30/31 的电源与 FPC1-27 的复位放在同一时序上判断。

### 3.7.2 触摸电源同时写高有效和低有效，应怎样解释现象

先按消费者的绑定解释。这里 fixed regulator 的兼容逻辑由 `enable-active-high` 决定极性，会忽略冲突的低有效标志，生成高电平使能。若 GPIO3_D0 高而 `VCC3.3TP` 不起，应检查 Q3/Q1 和上游电源；换成另一驱动控制同一线时，则需重新检查它的极性处理。

### 3.7.3 为什么开启 SDMMC0 可能改变屏幕供电

当前 IO DTS 的四位 SD 总线与产品面板电源都使用 GPIO1_D5。pinctrl 只能把这根脚接到一种内部功能，硬件也只有一根线。交付 DTB 禁用了 SDMMC0，源码重建若恢复该节点，就改变了这个前提；一次看似只涉及存储的配置变化会因此影响屏幕工作条件。
