### overlay 包的源码和hooks在哪里

两个包的共同前缀为 `usr/src/radxa-overlays-0.2.4/`。在此前缀下寻找：

- `dkms.conf`：包名、版本、自动构建及回调入口。
- `dkms.post_build`：按内核和架构保存DTBO。
- `dkms.post_install`：链接目标内核overlay目录，必要时调用rsetup。
- `dkms.post_remove`：对应清理行为；本任务只读，没有执行。
- `Makefile` 和 `arch/arm64/boot/dts/rockchip/overlays/Makefile`：构建子目录与插件目标。
- `arch/arm64/boot/dts/rockchip/overlays/aircas-compact-GCS.dts`：普通产品描述。
- PWM包额外的 `arch/arm64/boot/dts/rockchip/overlays/aircas-compact-GCS-pwm.dts`：197项亮度表的变体。

控制档案的 `postinst` 负责进入DKMS生命周期；数据档案内的 `dkms.post_install` 是构建后的安装回调。它们名字相似、所处阶段不同，不能视为同一个脚本。

### 在已有 Debian/Ubuntu 主机上复核包内容

以下是**只读复核示例，本次未在目标板运行** 。假设当前目录为项目根目录，已有 `dpkg-deb` 与 `tar`；路径中的文件确实来自本项目。它们读取包，不安装包，也不运行维护脚本。[Debian dpkg-deb 手册](https://manpages.debian.org/bookworm/dpkg/dpkg-deb.1.en.html)

```sh
# 看包身份及依赖，区别文件名与包内部版本。
dpkg-deb --field debs/radxa-overlays-dkms_pwm.deb Package Version Architecture Depends

# 找到CM3 DTB与风扇模块的准确包内路径。
dpkg-deb --contents debs/linux-image-6.1.84-12-rk2410-nocsf_6.1.84-12_arm64.deb | grep -E 'rk3566-radxa-cm3-io.dtb|pwm-fan.ko'

# 将配置成员送到标准输出，只筛选本章关心的编译项。
dpkg-deb --fsys-tarfile debs/linux-image-6.1.84-12-rk2410-nocsf_6.1.84-12_arm64.deb | tar -xOf - ./boot/config-6.1.84-12-rk2410-nocsf | grep -E 'CONFIG_TOUCHSCREEN_GT9XX|CONFIG_SENSORS_PWM_FAN|CONFIG_CHROME_PLATFORMS|CONFIG_THERMAL_DEFAULT_GOV'
```

第一项回答包内部身份；第二项回答成员是否存在；第三项回答编译选择。没有任何一项回答当前板是否绑定成功。读取其它成员时先从目录列表取得准确名字，避免凭文件名猜路径。

## 如何使用通用参考资料

各章引用 Linux v6.1 上游文档或源码，是为了解释 input、GPIO、devres、thermal等机制。它们不能替代这份 Rockchip/Radxa BSP 的匹配源代码。引用具体函数时，正文已区分本地实现与上游对照。

下列缺口需要保持可见：panel缺少匹配的完整解析器与恢复实现；CW2015缺少对应属性消费与换算代码；构建缺少锁定工程及补丁；启动缺少实际配置与日志；应用缺少消费者实现。相机、WFB-NG、ROS、QGC和飞控接口的现有材料只能支持其集成位置与所需条件。

## 自查与回答要点

1. **为什么同一函数名不足以证明两份代码相同？** 名字只标识接口或符号，函数体、宏、调用者和补丁仍可能不同。
2. **为什么同包名同版本也需要哈希？** 本项目已有具体反例：两个overlay包身份一致而内部亮度配置不同。
3. **源码行号失效后怎样继续定位？** 按函数、节点、属性或文档标题检索；先确认版本，再更新行号。
4. **想查某个现象应先翻哪个文件？** 先用[故障章节](11_故障排查与验证.md)确认层级，再按本索引定位对应源件，而不是遍历所有资料。
