# 01 项目总览

```text
系统分工
CM3：计算、存储、片上控制器
    + 自定义底板：接线、电源开关、接口与负载电路
    -> 设备树：资源位置、供电依赖、连接拓扑
    -> 驱动与子系统
       +-- DRM/VOP/DSI + panel + backlight -> 图像与照明
       +-- I2C/GT9XX -> input/evdev -> 触摸事件
       +-- CW2015 + gpio-charger -> power_supply -> 电源状态
       +-- TSADC/thermal -> pwm-fan/PWM -> 散热动作
```

核心资料是[CM3 DTSI](../../src/rk3566-radxa-cm3.dtsi)、[IO DTS](../../src/rk3566-radxa-cm3-io.dts)、[产品 overlay](../../设备树包/aircas-compact-GCS_overlay.dts)与[历史构建记录](<../../RADXA CM3地面站编译.docx>)。本章先把这些对象放回整个系统，再区分它们在构建、启动和运行中的作用。

## 1.1 从使用需要确定硬件职责

历史构建记录以高亮、低成本、具备散热能力的手持地面端为背景，选择 RK3566、2 GB LPDDR4、16 GB eMMC，并规划显示、触摸、电池监测、外部供电检测和通信接口。这解释了平台需求：屏幕负责输出，触摸负责输入，电量信息帮助判断续航，散热维持持续负载下的工作条件。

CM3 将 RK3566、内存、存储和部分供电支持集中在核心板上，经连接器引出信号；底板决定这些信号最后接到什么器件，并增加电源开关、保护、负载驱动和连接器。SoC 的 PWM 控制器只生成周期信号，背光的实际 LED 电流还要由底板上的供电与恒流电路建立。

同样，I2C 控制器能发送地址和数据，触摸芯片却要在正确电压、上拉、复位和地址选择条件下才会应答。板级适配的工作，就是把这些条件从电路连线落实为软件可以使用的资源，再按器件协议执行。

## 1.2 硬件描述与驱动通过资源和接口交接

把接线从驱动中分开，能让同一芯片驱动适应不同底板。设备树描述器件位于哪条总线、使用哪个地址、由谁供电及占用哪些引脚；驱动申请这些资源、初始化器件并处理数据；Linux 子系统规定同类设备向上层交付结果的方式。

| 层次 | 当前对象 | 向下一层交付什么 |
| --- | --- | --- |
| 物理电路 | 屏幕、电量计、风扇及其接线 | 可供电、复位、通信或控制的器件 |
| 硬件描述 | DTS/DTSI 与产品 overlay | 身份、地址、引脚、依赖和端点关系 |
| 驱动 | GT9XX、panel、CW2015、pwm-fan | 对器件的操作、状态和子系统注册 |
| 子系统 | DRM、input、backlight、power_supply、thermal | 显示提交、事件、亮度、供电属性和冷却接口 |
| 用户空间 | 桌面输入组件、显示服务、状态展示位置 | 用户可见画面、点击或状态 |

以一次触摸为例，INT 通知内核去取数据，I2C 返回芯片格式的触点记录，GT9XX 将它转换为 input 事件；evdev 把事件提供到 `/dev/input/eventN`，桌面输入组件读取后映射到窗口。`eventN` 是本次枚举的编号，`0x14` 则是 I2C 地址，二者属于不同层。[Linux input 接口](https://www.kernel.org/doc/html/v6.1/input/input.html)给出这些接口的通用关系，当前两套驱动的具体路径在第 07 章。

其他子系统采用不同交付方式：backlight 接收亮度请求，power_supply 提供属性查询，thermal 在内核中发出冷却请求。分层的价值在于复用，也在于排查时能找到明确的交接点：输入帧已正确却点击错位，就继续查用户态映射；总线还没读到有效帧，就先查采集链。

## 1.3 构建生成文件，启动建立条件，运行处理事件

### 1.3.1 构建与交付在产物处汇合

```text
内核源码、配置、板级 DTS -> 构建 -> 内核 + 模块 + 基础 DTB -> 内核包 --+
产品 overlay 源码 -> DKMS 源码包 -> 对应内核环境构建 -> DTBO --------+
发行版、桌面、程序、配置 -> RootFS ---------------------------------+
                                                                  |
                                                                  v
                                                    系统文件与启动选择
```

DTB 是基础设备树二进制，DTBO 是描述增补或覆盖的插件，RootFS 是程序、库、服务与配置所在的根文件系统。内核工程、overlay 工程和 RootFS 可以分别准备，再由镜像流程或现有目标系统组合。DKMS 在这里管理 DTBO 构建与安装，第 02 章会追到实际脚本。

### 1.3.2 初始化沿资源依赖推进

```text
启动程序选定内核与最终设备树 -> 内核建立设备模型
                                +-- 总线控制器就绪 --+
                                +-- GPIO/时钟/电源 --+-> 外设 probe
                                                        +-- 资源可用 -> 初始化 -> 接口
                                                        +-- 返回 -EPROBE_DEFER
                                                               -> 以后重试 probe
```

I2C 控制器先建立总线，挂接设备才能被创建；regulator 等提供者也必须能够响应资源申请。设备树的书写顺序不安排 probe 的先后。驱动把依赖未就绪正确返回为 `-EPROBE_DEFER`，驱动核心才能安排重试；吞掉错误则会改变这条路径。第 05 章以两套 GT9XX 的实际申请和回滚代码解释这个差别。

### 1.3.3 多条运行链共享平台并各自推进

```text
显示缓冲区 -> DRM/VOP -> DSI 像素 -> 已准备的 panel -> 图像
亮度请求   -> backlight 查表 -> PWM5/使能 -> 背光电路 -> 照明
手指变化   -> INT + I2C -> GT9XX -> input/evdev -> 用户态输入
电池状态   -> CW2015 周期更新 ----+
外部输入   -> GPIO 检测 ----------+-> power_supply -> 属性读取
SoC 温度   -> thermal 策略 -> 冷却请求 -> PWM0/风扇 -> 散热
```

这些路径在运行时并行。风扇不等桌面读完温度才调速，触摸也不等一次显示提交完成才读 I2C。它们会共享供电、CPU 时间或控制器资源，因此一个供电问题可以影响多个外设，而一个坐标变换错误通常只影响输入映射。

## 1.4 一块屏幕包含不同的数据与控制通道

显示像素由 VOP/VP 组织扫描，经 DSI Host/PHY 送到面板；panel 的供电、复位和初始化命令让它进入可接收画面的状态。背光单独提供照明，触摸单独报告手指位置。

所以“背光亮但无图像”应转向面板状态与像素通路；“有图像却亮度反向”应沿查表、PWM 极性和底板反相电路追踪；“触摸有事件却点错位置”则需要比较控制器坐标、驱动变换和桌面方向。把它们统称为屏幕初始化故障，会丢掉最有区分力的条件。

当前产品 overlay 描述面板原生 800×1280、`rotation=<90>`，触摸属性写 1280×800。尺寸交换提示横屏使用关系，但触摸最终量程还经过 CFG 与驱动路径，显示旋转也不自动旋转 evdev 数据。第 06、07 章沿同一组参数分别追踪。

## 1.5 版本组合决定具体行为

| 对象 | 当前材料中的差异 | 使用时先确定什么 |
| --- | --- | --- |
| 屏幕 | 阿美林 7 英寸与云奥 6 英寸 | 面板型号、初始化表、时序及触摸配置 |
| 底板 | 8 页地面站图与 3 页 `3566cam_internet` 图 | 实际连接器、GPIO 网络和供电电路 |
| GT9XX | 本地 V2.2、通用 V2.8.7、交付内核的修改线索 | 属性解析、编译宏、配置组与事件路径 |
| 基础树 | 本地 DTS 启用 SDMMC0，包内 CM3 DTB 禁用 | GPIO1_D5 是否与屏幕电源控制竞争 |
| overlay 包 | 同名同版本 0.2.4，普通/PWM 内容不同 | 实际包哈希和被选中的插件 |
| 系统路线 | 历史 5.10/Debian 11 与后续 6.1/Debian 12 | 内核、工具、RootFS 各自所属路线 |

当前内核包发行号为 `6.1.84-12-rk2410-nocsf`。公开内核基线由历史记录和打包标签定位到 `3bbac32`，本地移植与修改则要结合实际文件及包内容阅读；详细来源统一在[第 13 章](13_关键资料阅读索引.md)。

GPIO3_C1 在地面站 overlay 中承担面板复位，在相机底板图中却用于 LED。日期较新的图纸无法自动替代另一产品接线。同样，UART1 在基础 CM3 描述中连接 Bluetooth，使用飞控串口前要确定最终 pinmux 和占用，不能直接照抄历史规划中的编号。

## 1.6 把扩展能力接到正确位置

相机的控制支路包含供电、时钟、复位与 I2C，像素支路则经过 sensor、CSI/DPHY、CIF/ISP 和 V4L2。IMX415 与 GC2093 的 FPC 资料属于各自 sensor 方案；添加相机时，需要完成相应 endpoint 图再向采集程序交付帧。

无线图传消费网络与视频接口，地面站上层消费显示、输入及通信接口。历史记录提到 XFCE/X11、WFB-NG、ROS 和 QGC，这些名字用于定位集成层次；学习现有板级材料时，先把接口的供给和数据含义讲清，再沿实际应用入口继续。

下一章先追踪驱动和设备树如何成为系统文件，随后第 03～05 章从电路回到资源与初始化，第 06～09 章分别展开运行过程。

## 1.7 核心工程问题与深度理解

### 1.7.1 接上具有 DSI 和 I2C 接口的屏幕，剩下的适配工作是什么

还要建立器件工作的电气与协议条件。面板需要正确供电、复位、命令和像素时序；触摸需要地址选择、通知和数据解析；背光需要 PWM 与负载电路。设备树表达这块板的资源关系，驱动按对应型号执行，子系统再交付统一接口。

### 1.7.2 背光和触摸都工作，点击位置错误时应怎样收敛

先比较 input 事件的范围与四角方向，再比较桌面的映射。input 已符合约定而桌面错误，就查显示方向和用户态变换；input 已错，就追 CFG 与驱动变换。背光状态对这个坐标判断没有直接约束。

### 1.7.3 为什么同一份 overlay 换一个内核包后可能改变行为

基础 DTB 的启用状态、资源占用以及驱动的属性解析都可能变化。GPIO1_D5 与 SDMMC0 的组合就是资源差异；两套 GT9XX 的属性接口则是消费方式差异。因此要把基础树、overlay 和驱动作为配套关系阅读。
