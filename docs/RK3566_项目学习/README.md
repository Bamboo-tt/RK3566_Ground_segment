# RK3566 地面站板级适配学习指南

这套文档围绕一个问题展开：**怎样让一块具体的 CM3 底板，从“器件已经接上”走到“Linux 和上层能够正确使用”？** 从供电和接线出发，逐步理解设备树怎样表达硬件、驱动怎样取得资源、运行数据怎样进入标准接口，以及出错时怎样沿原路定位。

贯穿全文的主线是：硬件连接与供电 → 设备树及 overlay → 驱动与 Linux 子系统 → 标准设备接口 → 桌面及应用的使用位置。构建与交付说明这些软件从哪里来；启动初始化说明工作条件怎样建立；运行时说明器件怎样持续产生结果。三种流程分别展开，在产物与接口处衔接。

## 学习对象与资料边界

本项目采用 Radxa CM3/RK3566 与自定义底板。当前仓库保存设备树、两套 GT9XX 代码、Debian 交付包、屏幕资料、原理图和历史构建记录，适合深入学习板级适配。完整板级支持软件（BSP）工程、最终根文件系统（RootFS）镜像、当前启动日志和地面站应用源码尚未包含在这些材料中。因此，应用部分说明接口的消费位置；图传、遥测、任务管理等实现需要另外的源码或运行证据。

资料并非一套可以任意混用的最终装配清单。6 英寸与 7 英寸屏幕、两种底板图、两套触摸驱动、基础 DTS 与包内 DTB，以及普通/PWM overlay 包都有各自用途。正文先明确对象，再解释机制；详细定位集中在第 13 章。

## 阅读路线

前五章建立共同基础，六至九章沿不同外设深入，最后把所学用于部署核对、故障分析和完整讲解。第一次按顺序阅读；遇到某个机制需要回到原件时，再查索引。

具备基础 C/C++、GPIO 和总线知识即可开始。第 2 章先辨认“源码、描述数据、安装包、运行系统”之间的关系，不必立刻掌握全部构建命令；第 5～9 章再用具体外设把这些关系落到函数和数据上。遇到版本差异时，先确认自己正在跟踪哪一条链，再阅读对照分支，避免同时记两套调用关系。

## 证据怎样进入解释

全文用四类标记区分已有依据与知识缺口。前三类说明已掌握的证据，“待确认事项”指出还缺什么，本身不是验证结果。连续解释同一个对象时，可在段落或小节开头说明依据，不在每句话前重复标签。

| 依据或状态 | 能说明什么 | 还需要什么才能说明当前整机效果 |
| --- | --- | --- |
| 源码事实 | 当前代码、节点、属性及调用关系 | 确认实际构建与启动采用该版本 |
| 包内事实 | 指定哈希的包中包含哪些配置、符号、文件和 DTB 属性 | 确认安装、启动选择与驱动绑定 |
| 资料记录 | 原理图设计、供应商参数、历史操作与当时结果 | 核对当前实物和软硬件组合 |
| 待确认事项 | 明确指出尚缺的源码、日志、配置或测量 | 通过对应检查缩小或补齐缺口 |

解释所必需的 Linux 通用机制另行标明。上游驱动怎样实现，不等于这份 BSP 已采用完全相同的代码；配置里存在某个值，也不等于已经测出对应波形。故障章节据此把检查组织成“能够证明什么、仍不能证明什么”的推理过程。
