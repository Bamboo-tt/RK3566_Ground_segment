# RK3566 地面站板级适配：项目学习入口

这套文档的目标，是让你能够从一根硬件连线讲到 Linux 接口，再说明它如何进入构建产物、怎样在启动后生效，以及故障时应在哪一层寻找证据。

**项目主线：硬件连接与供电 → 设备树和 overlay → 驱动与 Linux 子系统 → 标准设备接口 → 桌面及应用的使用位置。**

当前目录的主体是 Radxa CM3/RK3566 的板级适配材料：基础设备树、产品 overlay、两套 GT9XX 触摸代码、Debian 交付包、屏幕资料、原理图和历史构建记录。完整 BSP 工程、RootFS 镜像及地面站应用源码并未包含在这里。学习中可以解释已有外设链路，不能把图传、遥测、任务管理或 ROS 应用补写成已经实现的系统。

本套文档新增于 2026-10-06。原有[全局架构与技术剖析](../../全局架构与技术剖析.md)、Word、源码、设备树、安装包和硬件资料均保留。旧分析作为查找线索；本套正文重新对照当前文件，并补充了旧触摸驱动的 IRQ 注册方式、条件化多点上报和温控执行条件。

## 贯穿全书的三种流程

| 流程 | 开始于 | 结束于 | 不应混入的内容 |
| --- | --- | --- | --- |
| 构建与交付 | 源码、配置、补丁、包选择 | 内核/DTB、DTBO、安装包及可启动系统内容组合 | 不能把触摸中断或 PWM 输出画成编译步骤 |
| 上电与初始化 | 引导程序交给内核的实际硬件描述 | 总线、资源和设备驱动建立工作条件，注册接口 | 不能把 DTS 的文本顺序当成执行时序 |
| 运行时工作 | 触摸、绘制、供电变化、温度变化等事件 | input、DRM、backlight、power_supply、thermal 等接口产生结果 | 不能把“安装了包”放在每次事件处理的调用链上 |

屏幕组件内部也要分开理解：显示像素走 DSI；触摸数据走 I2C，中断走 GPIO；背光通过 PWM 和使能电路控制。它们会共享供电与上层体验，但不共享同一条数据通道。

## 如何阅读证据标记

正文采用四种项目证据标记，另将解释所必需的 Linux 通用机制标出：

- **源码事实** ：当前 `.dts/.dtsi`、驱动、Makefile 或配置文本明确表达的内容。它能证明代码如何写，不能单独证明目标板执行了它。
- **包内事实** ：直接读取现有 `.deb` 的控制信息、脚本、内核配置、符号或 DTB 得到的内容。它能证明这个包带有什么，不能证明实板安装或启动了它。
- **资料记录** ：Word、原理图、面板表格等中的设计或历史操作记录。原理图描述设计连线；历史成功描述当时的结果。
- **待确认事项** ：需要匹配的完整源码、目标系统信息或实板测量才能成立的结论。

**通用原理** 不新增一种“项目成功证据”。例如，Linux 支持延迟探测，并不等于某个厂商 probe 正确传播了延迟探测错误；上游驱动如何处理默认亮度，也不证明 BSP 中同名驱动逐字相同。

每章末尾保留少量自查问题及回答要点。先不看答案，用自己的话复述“谁执行、拿到什么资源、交给谁、失败停在哪里”，比背文件名更能检验理解。

## 本套文档的验证范围

本次在主机上读取了现有材料，核对关键调用关系、包内配置与 DTB、版本差异和原理图关键页，并检查新增 Markdown 的链接、结构和图形渲染。原始文件保护检查以内容哈希为依据。

本文没有把主机阅读提升为完整内核编译、DT schema 验证、安装、刷机、启动、硬件波形、触摸实测或户外验收。正文中的板端命令均为**后续检查示例，未在目标板执行，不附虚构实测输出** ；所需工具缺失时先记录缺口，不把安装工具作为这次文档任务的一部分。

最后应建立的证据关系是：**实际底板 → 配套源码与补丁 → 具体包与配置 → 实际启动设备树 → 实际绑定驱动 → 接口读数或事件 → 上层消费结果** 。阅读顺序就是逐步补齐对这条关系的理解。
